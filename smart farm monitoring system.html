Smart Farm
Monitoring System

A low-cost embedded system designed to monitor agricultural conditions, detect nearby animal intrusion using ultrasonic sensing, detect rainfall, activate a local buzzer and send SMS alerts to the farmer through GSM communication.

Explore System Viva Preparation

Project Overview

Understanding the complete system from problem to implementation.

01 • PROBLEM

Farm Protection

Unattended agricultural fields can be affected by animal intrusion and sudden rainfall. Continuous manual monitoring is difficult, especially in remote areas and at night.

02 • PROPOSED SOLUTION

Automated Monitoring

Arduino Uno receives information from sensors and decides when an event has occurred according to programmed conditions.

03 • ALERT

Local + Remote

A buzzer gives an immediate local warning while the GSM module sends an SMS to the farmer through the cellular network.

Components

Every hardware element and its role in the system.

Arduino Uno

Central microcontroller. It reads sensor inputs, executes the program and controls the buzzer and GSM module.

Core: ATmega328P • 5V logic • 16 MHz

HC-SR04 Ultrasonic

Measures distance by transmitting ultrasonic waves and measuring the returning echo. Used here for animal/object detection.

Key: VCC, TRIG, ECHO, GND • 40 kHz typical

Rain Sensor

Detects water on a conductive sensing plate. Common modules provide analog and digital outputs.

Common module: LM393 comparator + potentiometer

SIM900A GSM

Provides cellular communication. Arduino sends AT commands to the module to send SMS alerts.

Interface: TX/RX serial communication

Buzzer

An audible output device used for immediate local warning when rain or intrusion is detected.

Power Supply

Provides stable electrical power. GSM modules can require high current during transmission, so its supply must be suitable for the exact board.

Ultrasonic Sensor — Inside & Working

Transmitter

One ultrasonic transducer emits a burst of high-frequency sound, typically around 40 kHz for HC-SR04.

Receiver

The second transducer receives the reflected sound wave after it hits an object.

TRIG & ECHO

Arduino gives a trigger pulse to TRIG. ECHO returns a pulse whose duration represents the travel time of the ultrasonic signal.

Distance Formula

Distance ≈ Time × Speed of Sound ÷ 2
The division by two accounts for the outgoing and returning paths.

Rain Sensor — Inside & Working

Conductive Plate

Parallel conductive tracks are exposed to water. Water changes the electrical conductivity between the tracks.

LM393

Common rain sensor modules use an LM393 comparator to compare the sensor signal with a reference level.

Potentiometer

The onboard potentiometer adjusts the threshold/sensitivity for the digital output.

AO & DO

AO provides an analog signal. DO provides a digital threshold signal. Your code reads the digital input.

GSM Module — Communication

What is GSM?

GSM is a cellular communication technology. With a SIM card and network coverage, the module can send SMS messages.

TX / RX

TX transmits serial data and RX receives serial data. The devices normally use crossed TX/RX connections and a common GND.

AT Commands

Your program uses AT+CMGF=1 for text SMS mode and AT+CMGS to specify the destination and start an SMS.

Power

Cellular transmission can create current peaks. Use the power requirements of the exact SIM900A board and a stable supply.

Methodology

How the hardware and software are integrated.

Step 1 — Initialization

Arduino starts serial communication, initializes the GSM interface and configures sensor and buzzer pins.

Step 2 — Sensing

The rain sensor is read and the ultrasonic sensor is triggered to obtain an echo duration and calculate distance.

Step 3 — Decision

Arduino compares sensor readings against programmed conditions such as rain status and the selected distance threshold.

Step 4 — Local Alert

When a condition is detected, the buzzer is switched ON to provide an immediate audible warning.

Step 5 — Remote Alert

The GSM module is instructed to send an SMS containing the detected event.

Step 6 — Repeat

The loop continues so the farm remains under continuous monitoring.

Core Arduino Program

Program structure used in the submitted prototype.

#include <SoftwareSerial.h>

SoftwareSerial sim(10, 11);

#define TRIG 9
#define ECHO 8
#define RAIN 7
#define BUZZER 4

int waterLimit = 10;

void sendSMS(String msg) {
  sim.println("AT+CMGF=1");
  delay(500);
  sim.println("AT+CMGS="+91XXXXXXXXXX"");
  delay(500);
  sim.println(msg);
  delay(200);
  sim.write(26);
  delay(2000);
}

void setup() {
  Serial.begin(9600);
  sim.begin(9600);

  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
  pinMode(RAIN, INPUT);
  pinMode(BUZZER, OUTPUT);

  digitalWrite(BUZZER, LOW);
}

long getWaterLevel() {
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);

  long duration = pulseIn(ECHO, HIGH);
  long distance = duration * 0.034 / 2;
  return distance;
}

void loop() {
  int rain = digitalRead(RAIN);
  long level = getWaterLevel();

  if (rain == LOW) {
    digitalWrite(BUZZER, HIGH);
    sendSMS("Alert: Rain Detected in Field!");
    delay(5000);
  }

  if (level < waterLimit) {
    digitalWrite(BUZZER, HIGH);
    sendSMS("Alert: Water Level High in Field!");
    delay(5000);
  }

  digitalWrite(BUZZER, LOW);
  delay(1000);
}
Code viva point: The function is named getWaterLevel() and the variable is waterLimit, but the HC-SR04 physically measures distance. In the animal-detection version, these names can be changed to getDistance() and animalDistanceLimit for clearer documentation.

Results & Discussion

Sensor Response

The ultrasonic sensor provides distance information and the rain sensor provides rainfall status to Arduino.

Alert Mechanism

The buzzer provides immediate local notification while GSM provides remote SMS notification.

Practical Advantage

The system can operate without Wi-Fi, making cellular SMS useful where internet access is limited but GSM network coverage is available.

Limitation

Ultrasonic sensing alone identifies nearby objects by distance; it cannot reliably identify an animal species. More advanced recognition would require additional sensing.

Future Innovations

Possible upgrades to turn the prototype into a more complete smart farming platform.

Farmer Mobile App

A dedicated application can display sensor status, receive alerts, store event history and provide a simple dashboard for farmers.

AI Animal Recognition

A camera and AI model could distinguish harmful animals from people or harmless movement, reducing false alerts.

IoT Dashboard

Internet connectivity can be added where available for remote data logging, graphs and long-term analysis.

More Sensors

Soil moisture, temperature, humidity and light sensors can provide wider environmental monitoring.

Solar Power

Solar charging with a battery can make the system more suitable for remote farms with limited electrical infrastructure.

Automatic Irrigation

A relay and pump can be added so soil-moisture readings can automatically control irrigation.

Conclusion

The Smart Farm Monitoring System demonstrates how a microcontroller, sensors and cellular communication can be combined to provide automated farm monitoring. The Arduino Uno processes information from the ultrasonic and rain sensors, while the buzzer and GSM module provide local and remote alerts. The design is simple, economical and suitable as a prototype for improving farm awareness and reducing dependence on continuous manual observation.
