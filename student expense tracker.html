Student Expense Tracker

A complete explanation of what the project is, why it is useful, the technologies used to build it, how its features work, how data is stored, and how the complete system operates.

1. What is a Student Expense Tracker?

The Student Expense Tracker is a web-based personal finance management application designed specifically for students. It allows a student to record income and expenses, organize spending into categories, set a monthly budget, monitor the remaining balance and understand spending patterns.

Instead of writing expenses in a notebook or trying to remember them, the user can enter each transaction into one digital dashboard. JavaScript processes the entered information and immediately updates the balance, monthly spending, budget status, charts and reports.

In simple words: It is a digital notebook + calculator + budget planner + spending report in one webpage.

6. How Data Storage Works

The current application uses the browser's localStorage. This is a built-in web storage mechanism that stores small amounts of data as key-value pairs.

Example transaction object

{ id: 123456789, date: "2026-09-09", desc: "College canteen", amount: 180, type: "expense", category: "Food", method: "UPI", note: "Lunch" }

Saving data

localStorage.setItem( "studentExpenseTracker_v1", JSON.stringify(data) );

Reading data

const data = JSON.parse( localStorage.getItem("studentExpenseTracker_v1") );
Viva point: localStorage is not the same as a cloud database. The data is stored in the browser on that device. Clearing browser site data can remove it.

7. Important Calculations

CalculationFormulaPurpose
BalanceTotal Income − Total ExpensesShows the remaining money.
Monthly ExpenseSum of current month's expense transactionsShows current-month spending.
Budget RemainingMonthly Budget − Monthly ExpensesShows how much can still be spent.
Budget Used %(Expenses ÷ Budget) × 100Shows progress toward the spending limit.
SavingsMonthly Income − Monthly ExpensesShows money left after spending.
Savings Rate(Savings ÷ Income) × 100Measures how much of income remains.

Example

If monthly income = ₹15,000, expenses = ₹8,000, and budget = ₹10,000:
Balance from these monthly values = ₹15,000 − ₹8,000 = ₹7,000
Budget remaining = ₹10,000 − ₹8,000 = ₹2,000
Budget used = (₹8,000 ÷ ₹10,000) × 100 = 80%
Savings rate = (₹7,000 ÷ ₹15,000) × 100 ≈ 46.7%

8. How the Charts Work

Spending Overview

The spending overview checks each day of the current month, adds expense amounts for that date and plots the values on a line chart. This helps identify days when spending was unusually high.

Category Breakdown

The category chart groups expenses into categories such as Food, Transport, Education and Entertainment. Each category's total is calculated and its share is represented visually.

9. Complete System Workflow

  1. Page loads in the browser.
  2. JavaScript initializes the application.
  3. Saved transaction data is retrieved from localStorage.
  4. The dashboard calculates the current financial status.
  5. User opens the Add Transaction form.
  6. User enters transaction details.
  7. JavaScript reads the form values.
  8. A new transaction object is created.
  9. The object is added to the transaction array.
  10. The updated array is converted to JSON.
  11. JSON data is saved in localStorage.
  12. The dashboard, transaction table, budget information and charts are refreshed.
  13. If the budget crosses 80%, a warning is displayed.
  14. If the budget is exceeded, an exceeded-budget alert is displayed.
  15. The user can search, filter, delete or export transactions.

11. Limitations

  • Data is stored only in the browser and is not synchronized between devices.
  • There is currently no user login or account system.
  • There is no cloud backup.
  • Multiple users cannot share the same financial database.
  • The current application does not automatically connect to bank or UPI accounts.
  • Budget and transaction information must be entered manually.
These limitations are intentional for the current frontend version. They can be solved by adding a backend and database in a future version.

13. Viva / Presentation Questions

Why did you make this project?

To provide students with a simple digital tool for recording expenses, managing budgets and understanding spending habits.

Which technologies did you use?

HTML5 for structure, CSS3 for styling and responsive design, and JavaScript for application logic, calculations, storage, filtering and charts.

Why did you use JavaScript?

Because the application needs dynamic behavior such as adding transactions, calculating totals, updating the dashboard, filtering records and drawing charts.

Where is the data stored?

In the current version, transaction data is stored in the browser's localStorage.

What is localStorage?

It is a browser storage API that allows websites to save key-value data locally so it can remain available after a page refresh.

Is localStorage a database?

It is a client-side storage mechanism, not a full database system. It is useful for this simple single-user frontend application but is not suitable for a large multi-user system.

What happens when a transaction is added?

The form values are collected, converted into a transaction object, added to the transaction array, saved as JSON in localStorage and then used to recalculate and redraw the interface.

How does the budget warning work?

The application compares current-month expenses with the monthly budget. At 80% or more it displays a warning, and after the budget is exceeded it displays an exceeded-budget alert.

How are expenses categorized?

Each transaction receives a category such as Food, Transport, Education, Entertainment, Shopping, Bills, Health or Other.

Can this project use a real database?

Yes. A backend can be added and the localStorage layer can be replaced or supplemented with a database such as Supabase, Firebase or MySQL through an API/backend.

What is the difference between frontend and backend in this project?

The current project is primarily frontend. The browser displays the interface and executes JavaScript. A future backend would handle authentication, APIs, database storage, security and multi-device synchronization.

What is the main benefit of this project?

It gives students a simple visual way to understand and control their personal spending instead of relying on memory or manual calculations.
